ДИЗАЙН (рекомендованный, от простого к полному):

ЭТАП-ПИЛОТ = 2D screen-tiled (Forward+), НЕ сразу 3D froxel — ниже риск и проще матчинг:
- Экран делится на тайлы (напр. 16x16 или 32x32 пикселя -> сетка ~120x68 при 1080p; фикс количество тайлов, напр. 32x18, надёжнее чем фикс размер).
- Для каждого тайла — БИТМАСКА uvec2 (64 бита) активных ламп. Свет i задевает тайл, если его экранный bounding-rect (проекция сферы влияния радиусом range) пересекает тайл. Битмаска -> НЕ нужен flat index-list, шейдер просто перебирает выставленные биты (findLSB/битовый цикл).
- Почему uvec2/64 бита: совпадает с дефолтным капом max_shader_lights=64. Свет за пределами 64 (slot>=64) в битмаску не влезает — поэтому битмаск-путь ПРИВЯЗАН к капу<=64. Если юзер поднимет слайдер выше — либо клэмпить кластеризацию к 64 (остальные грузить как раньше, без кластера), либо перейти на index-list вариант (offset+count в grid-буфере + flat uint-список) — это отложенное расширение, НЕ для пилота.
- Построение битмасок: CPU в irl-core, per-frame, после prioritize/flush (top-K уже отобран, slot()<64). Для каждой из <=64 ламп: спроецировать её сферу влияния в экранные координаты (MC projection*view, камера-relative позиция уже в SSBO по commit 8a6e40b), получить min/max тайлы, выставить бит во всех перекрытых тайлах. Дёшево: 64 лампы x ~несколько тайлов. Компьют-шейдер НЕ нужен при N<=64.
- Плумбинг данных: новый SSBO (или UBO) с массивом uvec2 по числу тайлов + uvec2 tileCount/tileSize в хедере. Аддитивно к существующему LightBuffer (binding 7) — НЕ ломать контракт [[addon-light-buffer-ssbo]] (96б/6xvec4, MAX_LIGHTS 2048). Взять новый свободный binding. Зарегистрировать по образцу IrlSamplers/FramePipeline.
- Шейдер (инжект в каждый пак): в точке per-light цикла (irlite_lightSurface и аналоги, см. [[shader-irlite-glsl]]) вычислить tile = ivec2(gl_FragCoord.xy)/tileSize -> прочитать uvec2 маску -> перебирать ТОЛЬКО выставленные биты вместо `for i in 0..lightCount`. Гейт под #define IRLITE_CLUSTER (как IRLITE_SHADOWS) с фолбэком «нет буфера/выключено -> цикл по всем» — тот же паттерн master-gate.

ОПЦ. ЭТАП-2 = 3D froxel (если 2D недостаточно, напр. много ламп за стеной в одном экранном столбце):
- Добавить Z-слои (лог. распределение по глубине, напр. 16-24 слоя). Froxel = tileXY x Zslice. Фрагмент маппится по gl_FragCoord.xy + линейной глубине (реконструкция viewZ из depth).
- ГЛАВНЫЙ РИСК ПЕРЕЕЗЖАЕТ СЮДА: маппинг фрагмент->Zslice в шейдере ДОЛЖЕН побайтно совпасть с тем, как мод раскидывал лампы по слоям (та же near/far и та же slice-функция). У каждого пака своя реконструкция глубины/своё gbufferProjectionInverse — сверять на этапе recon. 2D-пилот этого риска НЕ имеет (тайл = gl_FragCoord.xy/tileSize, без глубины).
