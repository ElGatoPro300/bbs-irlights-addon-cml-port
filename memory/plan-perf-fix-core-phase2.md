КЛЮЧЕВЫЕ RECON-ФАКТЫ (легли в дизайн):
- Тень привязана к свету по стабильному id (аддон System.identityHashCode(form), редактор l.id) через sticky-карты ShadowBaker (spotTileOwner/pointSlotOwner) — сортировка/cap на upload теней НЕ ломает; ломает «мигание» СОСТАВА регистра: тайл отбирается после STALE_FRAMES=2 отсутствия, BlockShadowCache/VBO чистятся В ТОТ ЖЕ кадр (retainOnly по liveIds, ShadowBaker:773-782). => cap ТОЛЬКО на upload, регистрация всегда полная.
- mustBake-bypass бюджета легитимен: setShadowTile(i,myTile) публикуется ДО решения о бейке (spot :348 / point :551) — отложить бейк без правки публикации = шейдер прочитает чужой/неинициализированный тайл. shadowTile<0 в шейдере = «без тени» (свет полный).
- ГАММА-ПРЕДРАСЧЁТ (был в плане) ОТКЛОНЁН: премиза аудита неверна — pow(rgb,1/2.2) есть только в CR+RethinkingVoxels и только в surface/outline (2 места, VL везде сырой цвет «RAW LINEAR»); Photon = матрица rec709->rec2020; Bliss/BSL/Solas/IterationRP = no-op. CPU-предрасчёт гарантированно ломает 5 паков + VL в CR/RV; свободного per-light места в 96Б записи НЕТ (12Б паддинга хедера — глобальные, не per-light). Заодно: комментарии контракта «linear color» (LightBuffer.java:16-18, glsl:83) ЛГУТ — в SSBO сырой sRGB-пикер int/255 без декода; pow(1/2.2) в CR/RV = эстетическое ВЫСВЕТЛЕНИЕ (не decode, тот был бы ^2.2). НЕ переносить на CPU без ре-дизайна per-pack.

РЕАЛИЗОВАНО (irl-core, все правки в 3 файлах):
- C3 slot()-hashmap: LightRegistry — open addressing long->int, HASH_CAP=4096 (load<=0.5), mix64 (murmur3 fmix64), generation-stamp очистка O(1) в clear()+flush() (wrap -> Arrays.fill раз в ~2 млрд), probe ограничен HASH_CAP. Семантика 1:1 со старым линейным сканом (тот же id -> тот же слот-перезапись; count>=MAX -> -1 БЕЗ вставки; коллизии identityHashCode по-прежнему склеиваются — pre-existing). Standalone-реплика алгоритма ALL_PASS.
- C1 cap+приоритизация: LightRegistry.prioritize(camX,Y,Z) строит order[] merge-sort по score=max(0, dist-radius - [8.0 HYSTERESIS если был в прошлом upload-сете] - [64.0 BEAM_BONUS если beam>0]) asc, tie-break id (стабильно; поворот камеры score не меняет — дребезга от вращения нет). orderedIndex(k) с identity-fallback при orderedCount!=count. setUploadCap(int): 0/<0 = без лимита (core-дефолт => редактор без капа). flush() пакует top-K по order (при устаревшем order пересобирает от origin=камеры), пишет uploadedIds для гистерезиса. FramePipeline.frame(): prioritize после collect ДО bake => ShadowBaker раздаёт тайлы/бюджет по приоритету (ближние первыми). ShadowBaker: spot(:275+)/point(:505+) циклы через orderedIndex(k); liveIds/retainOnly — по полному набору, НЕ тронуты. Плумбинг аддона: IrliteConfig.maxShaderLights (ValueInt, default 64), слайдер BBSSettingsMixin getInt("max_shader_lights",64,0,2048), lang в L10nMixin (en), LightCollector.collect() первым делом setUploadCap(...) per frame. BEAM_BONUS добавлен оркестратором после ревью (2 ревьюера независимо: выпадение VL-луча из top-K = заметный поп издалека; beam-светы вылетают из капа последними).
- C2 троттлинг mustBake: ShadowBaker allowStaticBake(boolean)->allowStaticBake(int kind): BAKE_DEFERRABLE (только при staticBakeBudget>0, байт-в-байт старое), BAKE_MANDATORY (первый бейк/пере-назначение тайла: гейт mandatoryBakeBudget=max(1,budget), сбрасывается ПЕРЕД spot-циклом И ПЕРЕД point-циклом — раздельные пулы, spot не голодает point), BAKE_FORCED (leave-transition dyn->static: всегда разрешён, НЕ троттлится — корректность overlay). При отказе MANDATORY: LightRegistry.setShadowPending(i) (сентинел SHADOW_PENDING=-2) => flush ОМИТИТ свет из SSBO целиком («нет тени -> нет света», НЕ засвет сквозь стены — это был major r1, закрыт), ownership тайла сохраняется (acquireTile каждый кадр -> active свежий, краж нет), lastTile не обновляется => ретрай следующим кадром. Cold-start 32 ламп budget 4: прогрев ~4-8 кадров, ближние первыми, тёмный поп-ин вместо 112-пассового фриза. mustBake от кражи тайла фактически недостижим как отдельный случай (purgeDirtyState жертвы сносит lastTile => это first-bake).

РЕВЬЮ: r1 = 2 major (свет-сквозь-стены при отложенном первом бейке; троттлинг краж) + 5 minor — фикс-раунд закрыл оба major (SHADOW_PENDING-омит + раздельные mandatory-пулы); r2 = PASS/0 significant. ОСОЗНАННО ОСТАВЛЕННЫЕ minor (не чинить без причины): (1) uploadCap не гейтит бейк-циклы — капнутые светы всё ещё получают тайл/бейк (статик-бейк sticky ~разовый, зато карта тёплая при входе в top-K; ревьюерский «пекут каждый кадр» неверен для статики); (2) FORCED декрементит mandatory-пул — намеренно, ограничивает суммарный спайк кадра; голодание first-bake требует патологического потока leave-transitions (watch-item); (3) acquireTile==-1 (тайлов<кастеров, ranks 17+) по-прежнему светит БЕЗ тени сквозь стены — PRE-EXISTING, priority order даже улучшил (протекают дальние); лечить = отдельное решение (омит vs протечка = видимая тьма vs засвет); (4) prioritize сортирует и при cap=0 (редактор, N=2000: ~микросекунды, порядок кормит бейкер — приемлемо); (5) pending-светы едят cap-слот (transient прогрева); (6) mix64-оверхед при N=3 (наносекунды).
